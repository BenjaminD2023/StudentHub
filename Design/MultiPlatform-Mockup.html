One design system · three idioms

The three platforms share tokens (colors, typography, spacing, radius, shadows) and components (cards, rows, pills, timeline blocks, sync indicator, quick capture). What changes is how those components are arranged — the layout idiom each platform expects from users.

iPhone

5-tab bottom TabBar for one-handed reach. Each tab = own NavigationStack. Native List(.insetGrouped) with .swipeActions and .searchable. FAB for quick add. Sheet inspectors with detents.

iPad

NavigationSplitView with persistent sidebar (264pt) and main content. Two-column card grid for the Today dashboard. Sidebar items show count badges and Space color dots. Same swipe actions on lists.

Mac

Existing 3-pane: sidebar (244pt) + content + Command Hub (360pt). Refined toolbar with segmented control, sync status, and quick capture. The Command Hub pattern from v0.1 stays because Mac users love it.

Implementation strategy (SwiftUI)

  • Conditional shell — a single AppShellView branches on UIDevice.current.userInterfaceIdiom: .phone uses the new IPhoneShellView (TabView), .pad uses the new IPadShellView (NavigationSplitView), macOS uses the existing 3-pane AppShellView with the toolbar/sync refinements.
  • Shared view model — AppState, HubTask, HubNote, ScheduleBlock, Course, and CloudSyncService are reused unchanged. CloudSyncService already syncs across Mac/iPhone/iPad via the user's private iCloud database.
  • Per-platform views — each platform gets its own SwiftUI files under StudentHub/Views/IPhone/, IPad/, and existing macOS paths. They compose shared components from HubComponents.swift (new file: HubPageHeader, SyncStatusPill, QuickCaptureField, ScheduleBlockCard, etc.).
  • Zero data-layer risk — WorkspaceStorage and CloudSyncService are untouched. The redesign is purely additive at the view layer.

  • Refinements to AppShellView.swift for macOS (toolbar sync pill, quick capture, segmented control) — kept minimal to avoid disrupting Mac users
