Design rationale

This is the v1 proposal. Everything below reuses the existing AppState, HubTask, HubNote, ScheduleBlock, Course, and CloudSyncService — no data layer changes. Only the view layer on iPhone is new.

Why a bottom TabBar

  • Thumb reach. iOS HIG positions primary navigation at the bottom so it's reachable in one-hand use. The current top Menu picker forces users to reach the top of a tall phone.
  • Discoverability. Five always-visible tabs expose the full IA — Today, Tasks, Calendar, Notes, More — without burying features behind a menu.
  • Independent stacks. Each tab owns its own NavigationStack, so deep links (a task, a note) push into the right context without losing the user's place.

What changes in the SwiftUI implementation

  • New IPhoneShellView with a 5-tab TabView (guarded by if UIDevice.current.userInterfaceIdiom == .phone); macOS/iPad continue to use the existing shell.
  • Per-tab NavigationStack with .searchable, .swipeActions, and .refreshable (pull-to-refresh → triggers appState.syncNow()).
  • Replaces the custom hubPanel() cards with native List + .listStyle(.insetGrouped) for that "this is iOS" feel.
  • Editors open in .sheet with .presentationDetents([.medium, .large]) so users can keep the list as context.
  • New HubPageHeader keeps the existing eyebrow/title/subtitle pattern but respects Large Title size at 34pt.
  • CloudSyncService and WorkspaceStorage are unchanged — iCloud sync works automatically on iPhone the same way it does on Mac.

Accessibility

  • All tappable rows are ≥ 44pt (iOS minimum touch target).
  • Color is never the only signal — every Space indicator pairs a colored dot with a text label.
  • Dynamic Type supported: every text style maps to a Font token, not a hardcoded size.
  • Tab bar, search, and FAB are accessibilityLabel annotated.
